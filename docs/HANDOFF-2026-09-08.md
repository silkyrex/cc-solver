## The division of labour that is easy to get wrong

The task prompts say it out loud: *"where this prompt and the repo differ, the repo wins."*

- **What the solver OUTPUTS** — repo controls it. Adding a field needs no Notion edit.
- **What the task writes IN** — the Notion prompt alone controls it. Requiring a new input field
  always needs a prompt edit.

Missing that split is exactly how the 12-hour `pt_time` change crashed `take_action` (PR #5).

## The interpolated-bar strip, as shipped (2026-09-09)

Ray approved the solver-side fix over editing eight live task prompts. `ccsolver/bars.py` strips
the leading and trailing runs of padded bars and counts the sessions that actually traded.

**Why the solver and not the prompts.** The strip needs no new input field, so it ships by merging
to `main` — every task clones `main --depth 1` at wake and carries it on the next run. The two
alternatives (edit the bars instruction in all eight bar-pulling prompts, or pass the
`interpolated` flag through and strip in code) both meant eight hand-pastes into ~15 KB live
prompts, which is the process that produced every drift found in the Session 3 audit.

**How a padded bar is recognised.** Volume 0 AND a zero-range OHLC, or the feed's own
`interpolated: true` when a caller passes it. Verified live on 2026-09-09 against a 130-day pull:
SKHY is flat 149.00 with volume 0 before its first real session on 2026-07-10, SPCX flat 150.00
before 2026-06-12, CRCL has no padding at all. The pad price is the first real bar's OPEN carried
backward, which is why the size of a move spanning the boundary looks about right while its dates
and duration are fiction.

**The trap in the trim.** The provisional live bar built from `quotes.json` also has volume 0, and
with no `day_high`/`day_low` its OHLC collapse to the last price — so it matches the synthetic
signature exactly, and it sits at the end of the series where the trailing trim runs. `is_synthetic`
returns False for anything carrying `provisional`. Test:
`test_the_provisional_live_bar_is_never_stripped`.

**Interior padding is kept on purpose.** A gap inside a real history is a halt. Removing it would
close the gap and shift every streak count by a session the position did not live through. It is
counted as not-history by `real_count`, never deleted.

**The half that is not the strip.** Stripping alone would have made things worse: the padding is
what keeps a young name's bar count above the 21 an EMA needs, so trimming it turns a silently
wrong 21 EMA into a `None` where a price is expected — a crash. Below **30 real sessions** the
21 EMA read is now withheld and said out loud rather than computed:

| Where | Thin-history behaviour |
|---|---|
| `entry_state` | `ema21: null`, `thin_history: true`, and `entry_door` binds `4ema` — the same rule a held row with no `entry_door` gets |
| `exit_state` | `closes_against_21ema: null`, `door_21ema: "unknown"`. A silent `0` would read as "no pressure against the door" |
| `position_monitor` | pushes the row, same argument as `SIDE UNKNOWN`: a door that could not be read is an unmonitored position |
| deep break | still mandatory, because it is a 4 EMA test |

**Why 30.** 21 is the bare minimum for any 21 EMA value (it is seeded with the 21-bar average, so at
exactly 21 the line is that average and has not reacted to anything). 60, which the prompts already
ask for in raw bars, would have gone dark on roster names the day it shipped: SKHY had 41 real
sessions and SPCX 59. 30 leaves nine sessions of real trading past the seed. It is a judgment call,
not a derived number.

**Also cleaned:** `grader.grade_board` and `grader.miss_audit`. A Miss Audit window starting on a
padded bar dates a move from a session that never traded, and `flagged_before` compares the board's
`first_seen` against that phantom date — which can clear a genuine miss. A name with fewer real
sessions than the 20-session window is now skipped rather than measured across the pad.

**Not regenerated:** `examples/take_action.out.json`. It predates the PR #8 clock work and carries no
`time_check` block, so it was already stale; regenerating it would bake a wall-clock timestamp into a
committed fixture. The example runs clean and no verdict value changed — only `real_bars` and
`thin_history` are new.
